Dashed borders are written, debugged and not yet run — the two LoRA trainers have never completed a step, and nothing has been deployed to a customer.

Find the tasks

The hard one. Nobody ever labelled when work happened.

Model proposes windows

A 30k token digest of tickets, chat and commits goes to system.ai.qwen35-122b-a10b on the Unity Gateway, which returns start and end timestamps per task.

Refuse to ship a broken set

18 conversations, 131k tokens. Checked for: every tool call answered, no orphaned results, no conversation ending on a tool message, no window in both splits, no unknown tool name.

Technology choices, and why each one

Databricks Lakebase
Postgres, not a warehouse. The pipeline needs transactional writes from a long lived agent replay, and a real relational store for entity linking and time range slicing. Portgres and a vector store would both be the wrong shape.
4 schemas · 11 tables
Unity Gateway
A 122B model hosted in the same workspace as the data, so the detector never moves company data out. Priced at nothing, which is what makes re-running the whole window detection affordable.
system.ai.qwen35-122b-a10b
Responses API, not chat completions
The gateway's typed client silently drops reasoning_content and its serializer throws on an OpenAI shaped reply. Calling the route directly keeps the reasoning we need to audit a decision.
/ai-gateway/mlflow/v1/responses
Our own harness as the runtime
The trajectories are generated by the same ten tools the customer runs. That is the moat: the model is fitted to a harness we own and can put on every desktop, not to a generic tool calling format.
10 tools · Electron + Next
